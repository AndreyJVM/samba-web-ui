# Переход с ShareGuard на Sambryx

Новое имя приложения — **Sambryx (Самбрикс)**. Переименование не меняет протокол SSH,
API, права пользователей Samba или содержимое общих папок. Java-пакеты `mari.samba`
сохранены; главный класс теперь `SambryxApplication`.

## Адреса публикаций

| Назначение | Прежний адрес | Новый адрес |
| --- | --- | --- |
| GitHub | `AndreyJVM/shareguard` | `AndreyJVM/sambryx` |
| Docker Hub | `andreyvorobevaqa/shareguard` | `andreyvorobevaqa/sambryx` |
| Документация | `AndreyJVM.github.io/shareguard/` | `AndreyJVM.github.io/sambryx/` |
| JAR | `shareguard-<version>.jar` | `sambryx-<version>.jar` |

Новый адрес Docker Hub станет пригоден для установки после создания репозитория и первой
публикации образов. До этого используйте уже опубликованный старый образ. Существующие теги,
образы и Git-история не удаляются. Не рассчитывайте на перенаправление старого Docker-адреса.

После переименования GitHub-репозитория обновите remote в существующем checkout:

```bash
git remote set-url origin git@github.com:AndreyJVM/sambryx.git
git fetch origin
```

Не нужно заново клонировать репозиторий или удалять локальные настройки. Переименование
каталога checkout необязательно. Настройку проекта в редакторе обновляйте отдельно при смене пути.

## Существующая production-установка

Перед изменениями сохраните `.env` и согласованную резервную копию постоянных томов,
описанных в [production-инструкции](production.md). Проверьте фактическое имя проекта:

```bash
docker compose ls
```

В `deploy/production/.env`:

1. Добавьте `COMPOSE_PROJECT_NAME=shareguard-production`, если стек раньше использовал именно
   это имя. Для другого существующего имени укажите его точное значение. Новым установкам
   подходит `sambryx-production`.
2. Переименуйте `SHAREGUARD_IMAGE` в `SAMBRYX_IMAGE`. Значением сначала может оставаться
   прежний опубликованный образ; после выхода нового релиза задайте его конкретный тег/digest.
3. Сохраните пути TLS-сертификата, ключей, адреса и порты.

Если использовали переменную скрипта `SHAREGUARD_ENV_FILE`, замените её на `SAMBRYX_ENV_FILE`.

Не меняйте имя Compose-проекта, не выполняйте `down -v` и не создавайте новые тома взамен
существующих: это приведёт к запуску пустой установки. Имена сервисов и ключи томов оставлены
прежними, поэтому при сохранении project name Compose подключит прежние данные. Примените
новую конфигурацию через `scripts/production/run.sh` с прежним вариантом `--with-samba`, если он
использовался. После пересоздания панели потребуется повторный вход.

Учётные записи, SSH host keys, UID/GID, база Samba и файлы сохраняются в прежних томах.
Том `/etc` требует того же контролируемого обновления, что и до переименования.
Уже созданного SSH-пользователя и sudoers-файл на внешнем сервере переименовывать не требуется.

## Docker Hub: описание независимо от релиза

Источником описания служит `DOCKERHUB.md`. Workflow `Sync Docker Hub Documentation`
запускается при его изменениях в `master` и вручную через Actions. Выпуск новой версии не нужен.
После обновления отдельный шаг читает публичный Docker Hub API и проверяет полное совпадение
описания с файлом; короткая заглушка не считается успешной публикацией.

Для первого запуска создайте публичный репозиторий `andreyvorobevaqa/sambryx` и проверьте
repository secrets `DOCKER_USERNAME` и `DOCKER_PASSWORD`. Учётная запись должна иметь право
обновлять описание, а не только отправлять образы; для PAT action требует scope read/write/delete.
Не добавляйте токены в исходники или `.env.example`.

Перед закрытием задачи переименования нужно проверить:

- новый GitHub-адрес и публикацию Pages;
- наличие тегов стандартного и экспериментального образов в новом Docker Hub репозитории;
- полное описание образа и рабочие ссылки в нём;
- запуск нового образа и обновление существующего стека с сохранением томов.

Поиск точного имени и отсутствие одноимённых репозиториев не подтверждают юридические права
на обозначение или доступность доменов. Проверка проводилась 23 октября 2026 года.
