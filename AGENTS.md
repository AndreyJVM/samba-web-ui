# Правила работы с Sambryx

## Контекст проекта

Sambryx — веб-интерфейс управления Samba на Linux. Backend: Java 21 и Spring Boot; frontend: React, TypeScript и Vite. Связь с серверами выполняется по SSH. Обращайся с SSH-командами, учетными данными, конфигурацией Samba, правами файлов и сетевой экспозицией как с чувствительными областями.

## Работа с изменениями

- До правок проверь состояние Git и прочитай относящиеся к задаче файлы. Не перезаписывай и не включай в свою работу существующие пользовательские изменения.
- Держись задачи: не делай несвязанный рефакторинг и не добавляй тестовый код ради покрытия. При изменении поведения опиши подходящую проверку и её результат; если проверку не запускал, укажи это.
- Не создавай коммиты, не отправляй изменения и не запускай деплой, если пользователь отдельно этого не поручил.
- Секреты не помещай в код, Docker-образы, примеры конфигурации или Git. Не выводи их в логи.
- Не формируй команды ОС из непроверенного пользовательского ввода. Для SSH и локального выполнения используй безопасную передачу аргументов и проверяй границы доступа.
- Не меняй аутентификацию, авторизацию, сетевую экспозицию, production-конфигурацию, процедуры публикации или защитные настройки хоста без явного задания и объяснения последствий.
- Для Docker учитывай фактические требования запуска проекта; не ослабляй защиту контейнера или JVM без подтверждённой необходимости и описания компромисса.

## Внешние агенты

- Не считай, что Gemini CLI, Antigravity CLI или конкретная модель доступны как инструмент. Используй их только если доступность подтверждена в текущей среде.
- Если пользователь работает мостом между Codex и Gemini, подготовь самодостаточный промпт с целью, контекстом, разрешённой областью изменений, ограничениями, нужной проверкой и форматом отчёта. Явно попроси Gemini вернуть diff и перечислить выполненные команды. Не проси его коммитить, публиковать или менять production-системы без отдельного поручения пользователя.
